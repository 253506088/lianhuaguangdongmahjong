# 附近同桌（Android 1.3.0）

## 使用

1. 所有人安装同版本 Android App，连接同一个 Wi-Fi；也可由房主开启手机热点，其他人连接该热点。不需要移动数据或互联网。
2. 大厅选择“附近同桌”，填写昵称。房主选择莲花广麻、莲花麻将、山东麻将或血流；山东可选 258 / 乱将与是否允许吃牌。掉线 AI 托管默认关闭。
3. 房主“创建房间”，出示二维码。朋友在 App 内“扫码加入”，核对后确认加入；没有可用摄像头时可以粘贴二维码面板里的备用邀请内容。
4. 至少两位真人入座，所有真人准备后，由房主开始。其余座位自动使用普通 AI，三人和四人也适用。空位 AI 与真人掉线托管是两件独立的事。
5. 每局结束后真人点“继续”。没有倒计时。每局结束都换下一家坐庄，包括庄家胡牌或流局；座位东→南→西→北循环，场风也按东南西北循环。第 4、8、16 局都不会自动结束，积分累计。
6. 牌桌左上“房间”可以查看成员、二维码、调整掉线托管。仅房主可以解散，且需确认。普通玩家暂离保留原座位。

## 断线、后台与恢复

- 真人从不因考虑时间太长而自动出牌、过牌、确认下一局。山东报听 / 明搂后与血流锁手后仍遵循该约定；合法动作会受到对应规则的限制。
- 默认关闭托管：掉线座位保留，轮到其出牌、碰杠胡响应或下一局确认时等待本人。
- 房主开启托管：离线真人由普通 AI 接手。房主可在局中开关；关闭后不再开始新的机器人操作，重新连接的真人立即收回控制权，未完成的旧机器人决定不会覆盖其操作。
- 断线自动重试。重新打开 App 后，点“恢复上次房间”。同一房间重新扫码也会复用本机原有座位凭据。
- 房主进程重启后，恢复原监听端口、证书和房间，从当前局固定牌墙、骰子、开局分数与已确认动作恢复，重放完成后再下发视图。上一局分数不会被重复累加。
- 房主换了网络或热点地址后，重新出示二维码会刷新地址；朋友重新扫码仍回原座位。卸载 / 清除 App 数据会删除本机恢复凭据。
- Android 可能回收后台进程，因此建议房主保持游戏在前台。若房主被系统回收，其他人等待其重新打开并恢复房间。没有房主迁移到另一位玩家的机制。
- Wi-Fi 的“客户端隔离 / AP 隔离”、公司访客网络或 VPN 可能阻止设备互连；这种情况下可使用手机热点。

## 实现边界

- 这是局域网中的手机直连。没有公网发现、平台登录、公共信令、跨 NAT 中继，也不依赖旧 VibeHub SDK。Android 构建以 `master` 为入口；WebSocket 网页和 VibeHub 网页保留自己的联机装配。
- 原生 `NearbyBridge` 只接受 APK HTTPS 主框架消息。扫码使用内置 ZXing；TLS 使用 AndroidKeyStore 的 P-256 证书，加入方按二维码 SHA-256 指纹核验房主。未开启 mixed content、文件访问或任意 JavaScript Java 对象桥。
- `NearbySockets` 使用有界长度帧、有界发送队列、独立读写、心跳和断连事件。大快照不会依赖平台 SDK 分片。房主解散发送应用层结束消息并等待确认，再关闭传输。
- `room.ts` 管理房间、身份绑定、准备、托管、续局和恢复。每位真人独立恢复凭据，连接 ID 改变不会换座位。新玩家不能在已开始的牌局中占用 AI 或他人的座位。
- 客户端只提交权威端发出的单次决策 ID 与合法选项 ID；动作窗口、座位和重复请求由房主校验。手牌索引、碰杠胡内容、积分均不能由来客任意指定。
- 下发快照只包含接收者的暗牌、他人暗牌数量与公开信息；不包含牌墙顺序或其他人的恢复凭据。房主是受信任的权威设备。
- 传统玩法复用现有引擎和普通 AI，AI 计算在 Worker 中执行；血流复用确定性引擎并在 Worker 中运行。房间不会调用引擎的限时到期接口。
- 持久化仅保存当前局重放日志、成员与累计分数，不让无限场无限累积内存。动作先写入本地持久化再执行；存储失败会暂停并提示恢复。

## 验证命令

```sh
pnpm test --maxWorkers=2
pnpm exec playwright test --config playwright.offline.config.ts --workers=1
pnpm android:debug
cd android
./gradlew testDebugUnitTest
```

Windows 使用 `gradlew.bat`。本机 Chromium 下载版若无法启动，可使用已安装 Edge：PowerShell 设置 `$env:E2E_CHANNEL='msedge'` 后运行 Playwright。

原生双机验收使用两个可清空的模拟器，默认 `emulator-5554` 与 `emulator-5556`：

```sh
node scripts/android-nearby.mjs
```

脚本会重装并清空**调试应用**，通过实际 UI 建房、准备、出牌与续局，验证真实 APK、WebView、TLS、大快照、座位私有视图和解散通知。模拟器各自位于隔离 NAT 后，所以仅使用 adb 转发 TCP 到房主；游戏消息、TLS 握手和规则引擎均为实际实现。不会将浏览器内的模拟消息网络当作原生联机验收。

`NEARBY_RULES` 可指定逗号分隔的规则列表；`NEARBY_ROUNDS` 指定抵达的局序号。默认经典玩法进入第 5 局，其余玩法进入第 2 局。取证文件保存到 `tmp/nearby-native-evidence/`。

`NEARBY_RECOVERY=1` 会在普通对局前加入主客机杀进程恢复、默认等待与房主开启托管的验收。`NEARBY_EVIDENCE_DIR` 可指定独立取证目录，便于分别保存多组运行结果。

自动化覆盖二维码生成 / 离线解码往返；摄像头镜头实际识别、不同品牌手机的热点行为仍应在实体设备上补验。运行结果与失败后的修复记录见 [1.3.0 验证记录](verification-nearby.md)。
